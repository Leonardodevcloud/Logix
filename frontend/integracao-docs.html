API de Integração

Conecte o seu sistema à plataforma e crie corridas automaticamente. Este guia mostra, passo a passo, como enviar uma entrega, consultar o andamento, cancelar e receber avisos em tempo real — com exemplos prontos para copiar.

REST · JSONSem instalaçãoExemplos prontos
Para quem é este guia
Foi escrito para ser seguido tanto por um programador quanto por alguém que nunca mexeu com integrações. Se você não é técnico, entregue este link ao responsável pelo seu sistema (ERP, e-commerce, etc.) — ele terá tudo o que precisa aqui.

Como funciona

Toda a comunicação acontece por mensagens no formato JSON enviadas pela internet (uma "requisição"). O seu sistema envia os dados da entrega; a plataforma responde na hora com o número da corrida e, quando quiser, avisa o seu sistema conforme o entregador avança.

  1. Você recebe as credenciais. A central gera, no painel, um Código do cliente e os tokens da sua integração e te entrega.
  2. Seu sistema envia a corrida. Um POST para o endereço de criar corrida com os pontos de coleta e entrega.
  3. A plataforma responde. Você recebe o número da corrida (a "OS") e o link de rastreio para mostrar ao seu cliente.
  4. Você acompanha. Consulte o status quando quiser, ou configure um webhook para ser avisado automaticamente a cada etapa.

Credenciais e autenticação

Cada integração tem duas informações que identificam e autorizam o seu sistema. Elas são geradas pela central em Integrações → Nova integração e aparecem uma única vez — guarde em local seguro.

CredencialPara que serve
codClienteIdentifica a sua empresa/loja na plataforma. É público (funciona como o seu "usuário").
tokenÉ o segredo que autoriza a operação. Existe um token por operação, no formato <segredo>-gravar, <segredo>-status, <segredo>-cancelar e <segredo>-calcular.

As duas informações vão dentro do corpo (o JSON) de cada requisição — não há cabeçalho ou senha separada. Use o token correspondente à operação que está chamando.

Perdeu o token?
Por segurança o segredo não é exibido de novo. Na tela de Integrações, use Gerar novos tokens — isso cria um novo segredo e invalida o anterior (seu sistema precisará ser atualizado com os novos tokens).

URL base e formato

Todas as chamadas são POST com cabeçalho Content-Type: application/json para os endereços abaixo:

# Base
https://logix-production-61ae.up.railway.app/api/v1/integracao

# Endpoints
POST  /gravar     criar corrida
POST  /status     consultar andamento
POST  /cancelar   cancelar corrida
POST  /calcular   prévia de distância e valor
Importante: a resposta é sempre HTTP 200
O resultado vem no corpo da resposta. Sucesso traz a chave Sucesso; falha traz a chave Erro com a mensagem. Sempre verifique qual das duas veio antes de prosseguir.

Limites de uso

OperaçãoLimite
Criar corrida (/gravar)até 2 por segundo
Consultar status (/status)1 a cada 30 segundos
Calcular preço (/calcular)até 2 por segundo

Se ultrapassar, a resposta traz um Erro avisando — basta reduzir o ritmo e tentar de novo.

POST Criar corrida

/api/v1/integracao/gravar

Cria uma nova corrida na plataforma. O array pontos deve ter no mínimo 2 e no máximo 80 itens: o primeiro ponto é a coleta e os demais são as entregas.

Campos do corpo (JSON)

CampoTipoDescrição
tokentextoobrigatórioToken da operação: <segredo>-gravar.
codClientetextoobrigatórioSeu código de cliente.
pontoslistaobrigatórioColeta + entregas. Veja campos do ponto.
numeroPedidotextoopcionalNº do pedido/NF no seu sistema. Serve para você reconciliar e evita duplicar a corrida se a mesma requisição for reenviada (idempotência).
semProfissionaltextoopcionalSe "S", a corrida entra na fila mas não é ofertada automaticamente aos entregadores (a central despacha depois).
ordenartextoopcional"false" mantém a ordem dos pontos como enviada. Caso contrário, a plataforma otimiza a rota. Com "true", o limite é de 20 pontos.

Exemplo de requisição

POST https://logix-production-61ae.up.railway.app/api/v1/integracao/gravar
Content-Type: application/json

{
  "token": "<segredo>-gravar",
  "codCliente": "<seu código de cliente>",
  "numeroPedido": "1234",
  "semProfissional": "N",
  "ordenar": "true",
  "pontos": [
    {
      "rua": "Av. Tancredo Neves", "numero": "620",
      "bairro": "Caminho das Árvores", "cidade": "Salvador", "uf": "BA",
      "cep": "41820-020", "la": "-12.978", "lo": "-38.458"
    },
    {
      "rua": "R. das Flores", "numero": "100", "bairro": "Pituba",
      "cidade": "Salvador", "uf": "BA", "la": "-12.995", "lo": "-38.451",
      "procurarPor": "Maria", "telefone": "71 90000-0000",
      "numeroNota": "998", "obs": "Deixar na portaria"
    }
  ]
}

Resposta de sucesso

✓ 200 · Corrida criada
Sucesso traz o número da corrida (a OS) — guarde-o para consultar/cancelar depois.
{
  "Sucesso": "LX-1287",
  "detalhes": {
    "distancia": 8.7,
    "duracao": "00:21:00",
    "valor": "25.50",
    "obs": "",
    "urlRastreamento": "https://painel.ig-express.com/rastreio.html?t=a1b2c3d4e5f6"
  }
}
CampoDescrição
SucessoNúmero da corrida (OS). Use nas operações de status e cancelamento.
detalhes.distanciaDistância total da rota, em km.
detalhes.duracaoTempo estimado, no formato HH:MM:SS.
detalhes.valorValor da corrida em reais (calculado pela tabela de preço da sua loja).
detalhes.urlRastreamentoLink público para o seu cliente acompanhar a entrega no mapa.

Respostas de erro

✕ 200 · Falha na criação
O corpo traz Erro com a mensagem. Exemplos:
{ "Erro": "Favor, informar 2 ou mais pontos!" }
{ "Erro": "Endereço do ponto 1 obrigatório!" }
{ "Erro": "Limite de endereços excedido. Favor informar um número igual ou menor que 80 pontos." }
{ "Erro": "Token inválido" }
{ "Erro": "Só é permitido solicitar 2 serviços por segundo." }

POST Cancelar corrida

/api/v1/integracao/cancelar

Cancela uma corrida pela OS. Só é possível cancelar antes de a coleta começar. Se o entregador já estiver em coleta/rota ou a corrida já tiver sido entregue, a resposta é Alocado.

Campos do corpo (JSON)

CampoTipoDescrição
tokentextoobrigatório<segredo>-cancelar
codClientetextoobrigatórioSeu código de cliente.
OStextoobrigatórioNúmero da corrida a cancelar.
descricaoMotivotextoopcionalMotivo do cancelamento (fica registrado).

Exemplo de requisição

{
  "token": "<segredo>-cancelar",
  "codCliente": "<seu código de cliente>",
  "OS": "LX-1287",
  "descricaoMotivo": "Cliente desistiu antes da coleta"
}

Respostas

✓ 200 · Cancelada
{ "Sucesso": "Cancelado" }
✕ 200 · Não foi possível cancelar
{ "Erro": "Alocado" }              // já está em coleta/rota ou finalizada
{ "Erro": "Serviço não encontrado." }

POST Calcular preço

/api/v1/integracao/calcular

Retorna uma prévia de distância, tempo e valor sem criar a corrida. Útil para mostrar o frete ao seu cliente antes de confirmar.

Exemplo de requisição

{
  "token": "<segredo>-calcular",
  "codCliente": "<seu código de cliente>",
  "pontos": [
    { "rua": "Av. Tancredo Neves", "cidade": "Salvador", "uf": "BA", "la": "-12.978", "lo": "-38.458" },
    { "rua": "R. das Flores", "cidade": "Salvador", "uf": "BA", "la": "-12.995", "lo": "-38.451" }
  ]
}
✓ 200 · Prévia calculada
{
  "Sucesso": { "distancia": 8.7, "duracao": "00:21:00", "valor": "25.50" }
}

Link de rastreio

Toda corrida recebe um link público de rastreio (o campo urlRastreamento na resposta e nas notificações). Ele abre uma página com o mapa, a posição do entregador em tempo real e o andamento de cada ponto — pronta para você repassar ao seu cliente final.

No seu domínio, com a sua marca
O link é gerado no domínio da sua própria loja e a página aparece com o seu logo e as suas cores, automaticamente. Não é preciso configurar nada além da sua marca no painel.

Webhook de notificação

Em vez de ficar consultando o status, você pode receber os avisos automaticamente. Informe uma URL de notificação ao criar a integração (ou depois, no painel) e a plataforma enviará um POST para o seu sistema a cada etapa da corrida — com as coordenadas do entregador, para você acompanhar onde ele está.

Quando você é avisado

Status.IDMomento
0Entregador recebeu a corrida.
0.5Chegou no ponto de coleta.
0.75Confirmou a coleta / saiu em rota.
1Finalizou um ponto (enviado uma vez por ponto).
2Finalizou a corrida.
3Corrida cancelada.

Formato do aviso

POST  <sua URL de notificação>
x-lx-signature: sha256=<assinatura>
Content-Type: application/json

{
  "ID": "LX-1287",
  "Status": { "ID": 2, "Nome": "João Silva", "telefone": "71 90000-0000", "dataHora": "2026-08-24 14:30:00" },
  "UrlRastreamento": "https://painel.ig-express.com/rastreio.html?t=a1b2c3d4e5f6",
  "coordenadasMotoboy": { "lat": -12.995, "lng": -38.451, "em": "2026-08-24 14:29:50" },
  "valorServico": 25.5,
  "valorProfissional": 18.0,
  "referenciaExterna": "1234"
}

No momento 1 (ponto finalizado) vem também um bloco statusEndereco com os detalhes do endereço concluído:

"statusEndereco": {
  "codigo": "FIN", "codigoCompleto": "FINALIZADO", "descricao": "Endereço finalizado",
  "criadoEm": "2026-08-24 14:12:33",
  "endereco": {
    "ponto": 2, "enderecoCompleto": "R. das Flores, 100, Pituba, Salvador - BA",
    "dataColetado": "2026-08-24 14:12:33", "lat": -12.995, "lng": -38.451,
    "motivo": { "tipo": "sucesso", "descricao": "Entregue com sucesso" },
    "obs": "Deixar na portaria", "numeroNota": "998"
  }
}

No momento 3 (cancelamento) vem o bloco cancelamento:

"cancelamento": { "descricaoMotivo": "Cliente desistiu antes da coleta", "temMulta": false }

Como confirmar que o aviso é legítimo (assinatura)

Cada aviso vem com o cabeçalho x-lx-signature. Ele é um HMAC-SHA256 do corpo exato da mensagem, usando o segredo do webhook (mostrado na criação da integração). Para validar: calcule o HMAC do corpo recebido e compare com o cabeçalho.

# Node.js
const crypto = require('crypto');
const esperado = 'sha256=' + crypto.createHmac('sha256', SEGREDO_WEBHOOK)
  .update(corpoBrutoDaRequisicao).digest('hex');
if (esperado !== req.headers['x-lx-signature']) { /* rejeitar */ }
Boas práticas do webhook
Responda rápido (em até 5 segundos) com HTTP 200. O envio é feito uma vez por etapa; trate o recebimento como informativo e, se precisar do estado atual a qualquer momento, use a consulta de status.

Referência — campos do ponto

Cada item do array pontos aceita os campos abaixo. O primeiro ponto é a coleta. Cada ponto precisa de um endereço identificável: informe o endereço em texto (rua, cidade…) ou as coordenadas (la e lo). Quando as coordenadas vêm, elas são usadas diretamente.

CampoDescrição
ruaopcional*Logradouro.
numeroopcionalNúmero.
complementoopcionalApto, bloco, referência.
bairroopcionalBairro.
cidadeopcionalCidade.
ufopcionalEstado (2 letras).
cepopcionalCEP.
laopcional*Latitude.
loopcional*Longitude.
telefoneopcionalContato no ponto.
procurarPoropcionalNome de quem procurar / receber.
numeroNotaopcionalNº da nota fiscal do ponto.
obsopcionalObservação para o entregador.

* Informe o endereço em texto ou as coordenadas. Ao menos um dos dois é obrigatório por ponto.
